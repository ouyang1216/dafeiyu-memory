# 发送后记忆策略

本策略规定发送通道、DSH 适配器和调用方何时可以把“我说过”“已发送”等状态写入大肥鱼记忆。它不改变发送行为；没有投递证据时，模型输出、草稿和计划都不是已发生事件。

## 术语

- **成功投递确认（ack）**：发送通道或适配器针对同一条消息返回明确成功状态，例如发送接口返回 `ok: true`、`status: sent/delivered` 或携带消息 ID 的成功结果。ack 证明通道接受了投递，不代表用户已读或被人工处理。
- **失败或拦截**：通道返回错误、拒绝、blocked 或失败状态，或者请求未到达可发送状态。失败本身可作为“发送尝试失败”的已观察事件记录，但消息内容不得记录为已发送。
- **结果不确定**：超时、连接中断、无响应、仅看到本地模型输出，或没有可关联到同一条消息的结果。结果不确定不等于成功。
- **已观察事实**：用户输入、工具实际执行及返回值、带时间戳和来源的系统事件。模型生成的回复文本不因出现在会话中而成为外部发送事实。

## 写入判定

按以下顺序执行：

1. 确认待记忆内容是否声称“我说过”“已发送”“已通知”或“已完成投递”。不是此类内容时，按现有记忆规则判断。
2. 确认证据来自通道或适配器，并能关联到同一条消息。仅有模型回复、计划、草稿、预期结果或工具调用请求时，停止记录为已发生事件。
3. ack 成功时，才可调用 `remember` 或 `correct` 记录发送事件。来源填写通道名和 ack 或消息 ID（如有），正文说明实际发生的发送；不要写成用户已读或已回复。
4. 失败、被拦截或结果不确定时，不得写入“已发送”“我说过”或“已通知”。只有用户明确要求且证据可核验时，才可记录“发送尝试失败”或“被拦截”这一事件本身。
5. 没有 ack 但需要保留信息时，只记录可直接观察的事实：用户输入、工具执行及返回结果、收到的消息。模型自己的输出只能表述为草稿或生成内容，不能表述为对外发送成功。

## DSH 工具与当前适配器

- DSH 工具结果只能证明对应工具实际执行及其返回值；不能证明未调用的工具会成功，也不能把计划或意图写成既成事实。
- 发送工具明确返回成功 ack 时，按“写入判定”第 3 条记录。
- 当前部署没有可观察 ack 的发送工具或适配器时，默认不存在外部发送证据。可记录用户输入和已返回工具结果，不得声称回复已发出或已送达。
- 记忆工具 `remember` 或 `correct` 成功只证明记忆写入成功，不证明任何外部消息已发送。

## 写入前检查

- [ ] 事件类型是发送，而不是计划、意图、草稿或模型生成。
- [ ] 证据来自通道或适配器，并关联到准确的消息或任务 ID。
- [ ] 结果是明确成功，而不是超时、拦截、失败或未知。
- [ ] 正文没有把通道接受写成用户已读或已回复。
- [ ] 来源、时间和证据可复核；敏感凭据未进入记忆。

任意一项不满足时，不记录“已发送”“我说过”等既成事实。
